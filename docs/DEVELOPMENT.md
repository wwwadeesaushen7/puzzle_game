# Development and export

## Tools and existing checkout

Use the existing checkout. A Codex cloud task is already isolated; do not create a worktree unless explicitly requested. Tools: Godot 4.6.3 stable, Blender 4.3.2, Python 3.12, OpenJDK 21, Android build tools 36.0.0 and platform tools 37.0.1. Blender supplies NumPy for the asset generator. Pillow is used only by the optional GLB audit.

Cloud paths:

```sh
cd /workspace/astral-forge  # or your existing checkout directory
export XDG_CONFIG_HOME=/workspace/.config
export XDG_DATA_HOME=/workspace/.godot-user
export XDG_CACHE_HOME=/workspace/.cache
export ANDROID_USER_HOME=/workspace/toolchain/android-user
mkdir -p "$XDG_CONFIG_HOME" "$XDG_DATA_HOME" "$XDG_CACHE_HOME" "$ANDROID_USER_HOME"
godot --headless --path . --import
```

The game needs no server or environment variables. The XDG paths above keep editor data and development tools writable in this particular cloud machine. They are not required for ordinary desktop/mobile play. The cloud's virtual X display is a testing aid; processes must be restarted after restoring a snapshot.

## Regenerate original art and audio

```sh
blender -b -t 4 --python tools/create_assets.py
python3 tools/create_audio.py
godot --headless --path . --import
python3 tools/configure_imports.py
godot --headless --path . --import
python3 tools/audit_assets.py
```

All models are UV-mapped meshes, with applied bevels and assigned PBR materials, exported as GLB. Mobile variants use mesh decimation and 256-pixel maps. High variants use 1024-pixel maps. Import settings request S3TC/BPTC on desktop and ETC2/ASTC for Android. Both variants are in the project so the player can switch quality without downloading assets.

The generator is deterministic. Do not delete authored GLBs just to run the project; they are already included. `-- --special-only` regenerates the ice, lock and compartment meshes alone. Additional external assets are not required. Art direction can later add authored sculpted wear, higher-resolution texture sets, distinctive structural modules and baked lighting; no such production assets are represented as completed work here.

## Export templates

Install Godot **4.6.3** templates through the editor's Export Template Manager, or in this cloud machine:

```sh
python3 tools/install_export_templates.py --cache /workspace/toolchain/downloads --data /workspace/.godot-user
```

This verifies the official archive against its SHA-512 manifest and extracts only the Windows x64 and Android templates. Downloads use the configured HTTPS proxy and keep TLS verification enabled. The cloud download cache can be reused.

## Android

The default APK uses Godot's prebuilt export template; a custom Gradle build is unnecessary. Install a JDK and Android SDK, or use:

```sh
python3 tools/install_android_tools.py /workspace/toolchain
```

That script obtains Google's official metadata, verifies the archive digests, and installs API 36, build tools 36.0.0 and platform tools. It does not install an emulator. Configure Godot Editor Settings → Export → Android with the SDK and JDK directories. In this machine they are `/workspace/toolchain/android-sdk` and `/usr/lib/jvm/java-21-openjdk-amd64`.

For a local development key, use the standard Android debug keystore generated by the editor or `keytool`; the current machine keeps it outside the repository at `/workspace/toolchain/keys/debug.keystore`. **Never commit a signing key.** The debug alias/password are the Android development defaults, not release credentials.

```sh
godot --headless --path . --export-debug Android builds/android/AstralForge-debug.apk
/workspace/toolchain/android-sdk/build-tools/36.0.0/apksigner verify --verbose builds/android/AstralForge-debug.apk
```

The APK is arm64, fullscreen, sensor-oriented and offline. It supports portrait and landscape on phones and tablets. A production store release needs your release keystore, final application ID/versioning, store metadata and device QA. Neither a store upload nor a release signing identity is included.

## Windows

```sh
godot --headless --path . --export-release Windows builds/windows/AstralForge.exe
```

The executable embeds its game pack. Launch it normally for Compatibility rendering, or with `--rendering-method forward_plus` on a capable GPU. `-- --low` starts with Low quality. Authenticode signing is disabled; no Windows signing identity was supplied.

## Quality and performance

| Preset | Assets and scene | Renderer-dependent effects |
| --- | --- | --- |
| Low | Mobile meshes and 256px maps, reduced detail, no dust or dynamic shadows | No advanced effects |
| Medium | Mobile meshes and maps, scene dressing, modest particles, directional shadows | No screen-space effects |
| High | Detailed meshes, 1024px maps, 4× MSAA, more particles | SSAO/glow and soft shadows in Forward+ |
| Ultra | High assets and detail | Forward+ adds SSR, SSIL, volumetric fog and restrained far depth of field |

Android defaults to Medium, 85% 3D render scale and 30 FPS. Desktop defaults to High, full render scale and 60 FPS. Both can be changed. Godot handles frustum culling and imported mesh LOD; floor tiles use MultiMesh instancing. Colliders are simple boxes, with no rigid-body simulation. There are two directional lights (one shadow caster) and two unshadowed accent lights. Baked lighting is not used in these procedural world scenes.

30 FPS on lower-end supported phones and optional 60 FPS are targets, not measurements. Native-device thermal, memory, frame-time and battery testing remains necessary. Hints run a bounded solution search on a worker thread; if no continuation is proven within the budget, no coins are spent.

## Touch and responsive layout regression checks

`bash tools/test.sh` runs rule, save, scene and touch suites. The touch suite routes raw screen events through Godot's input system to exercise synthesized GUI clicks as well as the board's raw-touch handling. It verifies phone/tablet sizes from 600×1000 to 1280×800, including tall portrait and compact landscape, modal preservation, camera framing, and picking after rotation.

For software rendering, start `Xorg :99 -config "$PWD/tools/virtual_display.conf" -logfile /tmp/astral-Xorg.log -nolisten tcp -noreset`, then run `DISPLAY=:99 LP_NUM_THREADS=4 ASTRAL_TEST_FIXED_FPS=5 bash tools/test.sh --render`. Fixed simulation timing keeps software validation practical; it does not measure frame rate. Existing scene tests now pass viewport-local coordinates explicitly to `push_input`, including with Godot's small dummy headless window.

The v1.1.0 development signing key lives outside Git at `/workspace/toolchain/keys/debug.keystore`. Preserve it securely to keep future development APKs upgrade-compatible. The prior workspace's key was absent; v1.1.0 cannot replace the previous differently signed installation in place. Do not commit keystores or change signing identities silently.
